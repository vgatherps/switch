# switch-netconf

See [The network config file](../../../book/src/nic/config.md) and
[the config tool](../../../book/src/nic/netconf-tool.md) in the switch book.
Generate the API reference with `cargo doc -p switch-netconf --no-deps`.

The switch network config file (`dut.json`): a typed `Config`, discovery of it from a Linux interface, and binding the NIC to vfio-pci. It does not need DPDK.

Used by `switch-open` (which turns a `Config` into a running `Stack`) and `switch-nic`. Depends on `serde`, `serde_json`, `libc` and the vendored `smoltcp` (for address and MTU types).

## API

- `Config` and its parts `Device` (`Pci(PciDevice)` or `Vdev`), `PathRule`, `Offloads` (`Auto` or explicit checksum flags), `EalConfig`. `Config::load(path)` rejects unknown fields; `ConfigError` carries the reason. Fields: device, mac, ipv4, gateway, owned_ipv4, mtu, paths, offloads, rx_timestamps, descriptors, eal.
- `owned_ipv4` (optional, default empty, omitted from the JSON when empty): CIDRs the Stack owns besides `ipv4`, single addresses as /32; `switch-open` passes them to `StackConfig::owned_ipv4`. Each entry is checked against the Stack's rules (`smoltcp::iface::OwnedIpv4::new`): no host bits set, and no address it covers may be 0.0.0.0, multicast, 255.255.255.255, the gateway or the `ipv4` subnet's broadcast address. On load the list is sorted and duplicates and entries inside another are dropped. Ownership only: `ipv4` keeps routing, the subnet broadcast and the default source.
- `discover::{discover, discover_aws, ipv4_addresses}`: read the interface's IPv4, MAC, MTU, PCI address and id, kernel driver and NUMA node from the kernel. Fresh discovery sets the port MTU to the smaller of the NIC MTU and 1500; AWS VPC and default path rules use 1500, clamped to the port MTU at lookup. `discover_aws` also reads ENI facts from IMDSv2 (`imds`); `owned_ipv4` is every `local-ipv4s` address as a /32 plus every `ipv4-prefix` block (404: none). The primary `ipv4` is chosen as before.
- `rediscover::write`: writes a discovered config over an existing file. Discovered facts replace the old ones, except a previous port MTU above 1500 is retained (including values generated by older versions, which cannot be distinguished from user edits). Devargs, offloads, rx_timestamps, descriptors, eal, hand-added path rules, and `owned_ipv4` unless the source lists the interface's addresses, as `--aws` does, are kept. Rules whose `why` is `vpc` or `default` are regenerated; use another `why` for a custom path rule. It reports `changed: <key>` per changed field; a replaced `owned_ipv4` also gets one `owned_ipv4 removed: <cidr>` line per dropped entry (hand-added ones included) and one `owned_ipv4 added: <cidr>` per new one.
- `devbind::{bind, unbind}`: move the device between its kernel driver and vfio-pci, with refusals before any write.

`mac` is required for PCI devices and must be `null` for vdevs; a non-null vdev value is rejected.
If a bind write fails after the kernel driver was detached, including clearing the override after
vfio-pci bound, recovery detaches vfio-pci if needed, clears the override and rebinds the kernel driver.

## Binary

```sh
switch-netconf check FILE
switch-netconf discover --interface IF [--ipv4 ADDR] [--aws] [-o FILE]
switch-netconf bind FILE [--noiommu] [--dry-run]     # root
switch-netconf unbind FILE                            # root
```

Exit status is 2 for a usage error and 1 for a failure. The full procedure (hugepages, IOMMU, EC2 specifics) is in [../switch-nic/README.md](../switch-nic/README.md), sections 2 and 3.

## Test

```sh
make test-netconf    # cargo test -p switch-netconf -p switch-open -- --test-threads=1
```

Tests are in `tests/check.rs`, `discover.rs` and `devbind.rs`. Building the crate alone needs only a Rust toolchain; `make test-netconf` also runs the `switch-open` tests, which need DPDK.

`bind` and `unbind` write to sysfs and are meant for Linux hosts. `bind` taints the kernel with `--noiommu`.
